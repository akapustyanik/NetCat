# ТЕХНИЧЕСКОЕ ЗАДАНИЕ И СИСТЕМНАЯ АРХИТЕКТУРА: HYBRID-VPN (WINDOWS NATIVE)

## 1. Стек технологий и окружение

* **Целевая платформа:** Windows 10 / 11 (x64, ARM64).
* **Среда выполнения:** .NET 8.0 LTS (C# 12), Native AOT-совместимая архитектура.
* **Графический интерфейс:** WPF (DirectX/DirectWrite аппаратное ускорение), CommunityToolkit.Mvvm. Исключено использование Electron, CEF, WebView2 и сторонних веб-оберток.
* **Сетевой стек L3/L4:** Wintun Driver v0.14+ (L3 TUN-адаптер нулевого копирования).
* **Пакетный фильтр DPI:** WinDivert 1.4+ (модуль Zapret / `winws.exe`).
* **Бинарные ядра (управление дочерними процессами):**
* `sing-box.exe` (v1.9+) — первичный L3/L4 маршрутизатор, TUN-адаптер, DNS-резолвер, поддержка протоколов VLESS, VMess, Shadowsocks, Trojan, Hysteria2, TUIC.
* `xray.exe` (v1.8+) — вспомогательное ядро для расширенных конфигураций Xray-core (VLESS XTLS Reality, gRPC fallback).
* `openvpn.exe` (v2.6+) — поддержка классических конфигураций `.ovpn`.
* `winws.exe` (Zapret) — модификация заголовков TCP/UDP пакетов на физическом сетевом адаптере.


* **Хранилище данных:** SQLite / LiteDB (история задержек, метрики сессий), JSON (конфигурации, правила, манифесты).

## 3. Архитектура ядра и сетевого стека

### 3.1. Структурная схема взаимодействия модулей

```text

               |                  Физический сетевой адаптер                 |
               +-------------------------------------------------------------+
                                              |
                              [WinDivert / Zapret (winws.exe)]
                                (DPI Bypass: модификация пакетов)
                                              |
+---------------------------------------------v---------------------------------------------+
|                                    Wintun TUN Adapter                                     |
|                                    (172.19.0.1 / 30)                                      |
+-------------------------------------------------------------------------------------------+
                                              |
+---------------------------------------------v---------------------------------------------+
|                                   ГЛАВНЫЙ МАРШРУТИЗАТОР                                   |

+----------------------+--------------------+---------------------+-------------------------+
                       |                    |                     |
     +-----------------+                    |                     +-------------------+
     | Direct                               | Socks5 Bridge                           | Socks5 Bridge
     v                                      v                                         v
[Физический шлюз]              [127.0.0.1:10850]                         [127.0.0.1:10851]
                                       |                                         |
                            +----------v-----------+                  +----------v-----------+
                            |      Xray-core       |                  |     OpenVPN CLI      |
                            | (XTLS Reality/gRPC)  |                  |    (.ovpn config)    |
                            +----------------------+                  +----------------------+

```

### 3.2. Принцип Dual-Path Failover (Отказоустойчивость с нулевой задержкой)

Для обеспечения непрерывности соединения без разрыва активных сессий (TCP/UDP) реализуется гибридная схема:

1. **Синхронный TCP Racing (Active-Active):**
* При инициации нового TCP-соединения `sing-box` отправляет параллельные `SYN`-пакеты сразу через два независимых Outbound (например: Основной — VLESS-Reality через Sing-box; Резервный — Hysteria2 или локальный Xray bridge).
* Соединение, подтвердившее `SYN-ACK` с минимальным RTT, назначается рабочим для данного потока. Второе соединение завершается отправкой `RST`.


2. **Fallback-мониторинг постоянных сессий:**
* Фоновый сервис `HealthChecker` опрашивает конечные точки (`generate_204`) с частотой 1 раз в 5 секунд.
* При фиксации 2 последовательных потерь пакетов на активном канале `sing-box` переключает шлюз на резервный узел через internal unix-socket API без перезапуска TUN-интерфейса.



### 3.3. Модуль Zapret (DPI Bypass)

* Запуск: `winws.exe` запускается с аргументами, соответствующими активному профилю провайдера.
* Фильтрация трафика: задействуется WinDivert с фильтром:
`outbound and ip and (tcp.DstPort == 80 or tcp.DstPort == 443 or udp.DstPort == 443)`.
* Разделение ответственности: Zapret работает на L2/L3 до попадания зашифрованных VPN-туннелей в сеть, обрабатывая трафик, идущий в обход VPN (`Direct`), предотвращая блокировку самих VPN-нод и доступных напрямую сайтов.

## 4. Контракты интерфейсов и модели данных

### 4.1. Доменные перечисления и модели (`HybridVPN.Core`)

```csharp
namespace HybridVPN.Core.Enums
{
    public enum CoreType
    {
        SingBox,
        Xray,
        OpenVpn
    }

    public enum RoutingMode
    {
        Global,             // Весь трафик через VPN
        RuleBased,          // Маршрутизация по базам Geosite/GeoIP
        SelectiveVpn,       // VPN только для указанных приложений/доменов (Whitelist)
        SelectiveDirect     // VPN для всего, кроме указанных приложений/доменов (Blacklist)
    }

    public enum FailoverStrategy
    {
        ActiveActiveRacing, // Параллельная отправка SYN на 2 протокола
        HotStandby          // Мгновенное переключение при падении метрик
    }

    public enum NodeStatus
    {
        Active,
        Standby,
        Degraded,
        Dead
    }
}

```

```csharp
namespace HybridVPN.Core.Models
{
    public class ProxyProfile
    {
        public Guid Id { get; set; } = Guid.NewGuid();
        public string Name { get; set; } = string.Empty;
        public CoreType TargetCore { get; set; }

        public bool IsPrimary { get; set; }
        public bool IsBackup { get; set; }
        public LatencyResult LastMetrics { get; set; } = new();
    }

    public class RoutingRule
    {
        public Guid Id { get; set; } = Guid.NewGuid();
        public string Target { get; set; } = string.Empty; // "discord.exe", "domain:youtube.com", "geoip:ru"
        public RuleType Type { get; set; } // Process, Domain, IP, GeoData
        public RuleAction Action { get; set; } // Proxy, Direct, Block
    }

    public class LatencyResult
    {
        public int TcpPingMs { get; set; } = -1;
        public int RealHttpDelayMs { get; set; } = -1;
        public double PacketLossRate { get; set; } = 0.0;
        public DateTime Timestamp { get; set; } = DateTime.UtcNow;
    }
}
```

## 7. Системная интеграция и нативный UI

### 7.1. Работа с привилегиями Windows

* Работа с сетевыми драйверами `wintun.dll` и `WinDivert.dll` требует прав Администратора.
* Приложение компилируется с манифестом `requireAdministrator`.
* **Автозапуск без всплывающего UAC:**
* Автозапуск настраивается через Task Scheduler API (`ITaskService`).
* Создается задача `HybridVPN_AutoStart` с параметрами: `Run with highest privileges`, `At log on of any user`. Запись в ветку реестра `Run` не используется во избежание блокировок системы контролем учетных записей.



### 7.2. Жизненный цикл интерфейса и трей

* Класс `TrayIconManager`: использует нативные вызовы `Shell_NotifyIcon` через Win32 API.
* Событие `Window_Closing`:
* Если опция `MinimizeToTrayOnClose = true`, то `e.Cancel = true; this.Hide();`.
* Значок в трее отображает контекстное меню:
* Статус активного узла и пинг (зеленый/желтый/красный маркер).
* Быстрый селектор режимов: `Global`, `Rule-based`, `Selective VPN`, `Direct`.
* Пункт «Включить / Отключить VPN».
* Кнопка полного выхода.




* Штатное завершение приложения:
* Перехват событий `AppDomain.CurrentDomain.ProcessExit` и `Application.Current.Exit`.
* Гарантированная остановка процессов `winws.exe`, `sing-box.exe`, `xray.exe`, `openvpn.exe`.
* Сброс интерфейса Wintun и очистка добавленных статических маршрутов таблицы маршрутизации Windows.



### 7.3. UI / MVVM Спецификация

* **Кастомизация стилей:**
* Поддержка цветовых тем через сменные словари ресурсов: `DarkTheme.xaml`, `LightTheme.xaml`.
* Акцентные цвета сохраняются в `appsettings.json` и связываются динамическими ресурсами (`DynamicResource AccentColorBrush`).


* **Редактор конфигураций:**
* Встроенный компонент редактора JSON на базе AvalonEdit (без сторонних Web-редакторов).
* Подсветка синтаксиса JSON, валидация структуры схемы перед сохранением.


* **Мониторинг трафика:**
* Нативный компонент `TrafficGraph.xaml`, отрисовывающий `Polyline` через аппаратный контекст `DrawingContext` (DirectX/WPF) с частотой обновления 1 Гц (без выделения памяти под DOM-структуры).

## 8. Пошаговый сценарий сборки проекта через CLI

Для генерации каркаса проекта через командную строку выполнить следующий набор команд:

```powershell
# 1. Создание директории и Solution
mkdir HybridVPN
cd HybridVPN
dotnet new sln -n HybridVPN

# 2. Создание проектов архитектурных слоев
dotnet new classlib -n HybridVPN.Core -f net8.0
```
