# Следующий этап: обычный UI и привилегированный broker

Статус: проектирование, не реализовано в test.14. До перехода UI остаётся `requireAdministrator`.

## Граница ответственности

`NetCat.UI` запускается с обычным токеном пользователя. UI владеет настройками, подписками, редакторами, темой, тестами, планированием обновлений и `settings.dpapi`. Шифрование остаётся `DataProtectionScope.CurrentUser`. UI не передаёт broker произвольные команды, имена EXE или пути назначения.

`NetCat.Broker` — небольшой Windows service либо отдельный elevated-процесс, которому принадлежат только TUN, системные маршруты, OpenVPN, WinDivert/Zapret, управляемые Job Objects и установка проверенных обновлений. Одна machine-wide lease предотвращает двух владельцев сети. Пропадание клиента или истечение lease останавливает принадлежащие ему процессы и восстанавливает только его изменения маршрутов.

## IPC и авторизация

Типизированные запросы с version/request ID: `GetStatus`, `PrepareConnection`, `CommitConnection`, `RollbackConnection`, `StopConnection`, `SetServiceScenario`, `PrepareUpdate`, `CommitUpdate`. Ответы содержат подтверждённый revision и фактические идентификаторы процессов/адаптеров. Повторная отправка с тем же request ID идемпотентна.

Named pipe имеет явный ACL для разрешённого SID пользователя и SYSTEM/администраторов. Сервер получает SID, session ID, PID и start time клиента из Windows token/pipe API; значения из JSON не являются доказательством личности. Протокол ограничивает длину сообщений, время запросов и число ожидающих операций. `Show` остаётся отдельным непривилегированным каналом без сетевых полномочий.

Broker принимает ограниченные DTO, проверяет диапазоны портов, allowlist поддерживаемых операций, путь установки, владельца файлов и подписи доверенных модулей. Запрещены произвольные PowerShell, команды, загружаемые плагины и запись по переданному клиентом абсолютному пути. Каталоги выполняемых elevated-компонентов защищены ACL от непривилегированной записи. Логи не содержат токены и конфиги с секретами.

## Транзакции

UI строит desired snapshot из committed revision. Broker валидирует и подготавливает runtime с rollback token, затем применяет конфигурацию. UI атомарно сохраняет DPAPI и подтверждает commit. Если запись/канал пропали, broker возвращает прошлую конфигурацию по token; при невозможности восстановления останавливает соединение и публикует честное состояние. Для восстановления после падения хранится журнал без открытых паролей. Версия протокола и схемы журнала проверяются до любых изменений.

Для полного обновления используются доверенная подпись, тот же издатель, хеши манифеста, защищённый stage и durable journal test.14. UI лишь показывает план; broker устанавливает подтверждённый пакет. Смена сертификата — отдельная явно проверенная процедура, не сравнение только отображаемого имени издателя.

## DPAPI и UAC до миграции

При подтверждении UAC своей администраторской учётной записью SID не меняется. Если стандартный пользователь вводит пароль ДРУГОГО администратора (over-the-shoulder UAC), весь текущий NetCat работает с SID и `%LocalAppData%` этого администратора. Он не получает доступ к DPAPI-настройкам пользователя рабочего стола. Test.14 сравнивает пользователя WTS session и текущий SID и при обнаружении различия показывает предупреждение в статусе и журнале. Настройки автоматически не переносятся; переход на `LocalMachine` не используется.

## Критерии отдельного milestone

1. UI запускается без UAC; обычный пользователь владеет DPAPI и подписками.
2. ACL/identity tests включают другого пользователя, RDP session, PID reuse, пропавший клиент и повтор request ID.
3. Отказ/kill UI, broker и каждого child не оставляют TUN/WinDivert/маршруты; восстановление идемпотентно.
4. Транзакционные race/fault tests test.14 проходят через IPC; проверяются rollback и crash recovery обоих участников.
5. Подписанный install/update/restart проходит на чистой VM и стандартной учётной записи. Подлинная межсессионная проверка выполняется в VM, а не объявляется пройденной по тесту двух объектов в одном процессе.

Это отдельный выпуск после стабилизации test.14; массовый перенос сетевого кода в этом билде не выполнялся.
